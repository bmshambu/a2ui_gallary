Gemini Enterprise · A2UI rendering

How our A2UI components render in Gemini Enterprise

Interactive cards — forms, tables, tabs, sliders, modals — appear natively in the GE chat. Here is exactly how the payload travels from our agent to the screen, and where A2A fits in.

Are we using A2A, or only JSON?
Both. A2UI JSON is the content; the A2A protocol is the transport.
ContentA2UI v0.8 JSON surfaceUpdate · dataModelUpdate · beginRendering
TransportA2A DataParts mimeType application/json+a2ui — over the A2A protocol

The rendering pipeline

  1. { }
    A2UI JSON

    Build the components

    On every reply, the agent's after_model_callback runs builders that produce A2UI v0.8 messages — plain JSON, one surface described as three messages.

    {"surfaceUpdate":   {"surfaceId":"s","components":[…]}}
{"dataModelUpdate": {"surfaceId":"s","contents":{…}}}
{"beginRendering":  {"surfaceId":"s","root":"root"}}
  2. <>
    A2UI JSON

    Wrap for the wire

    ADK agent code can't emit a raw A2A DataPart directly, so to_genai_part() wraps each JSON message in a tag inside a text/plain blob.

    <a2a_datapart_json>{"kind":"data","data":{…A2UI…},
   "metadata":{"mimeType":"application/json+a2ui"}}</a2a_datapart_json>
  3. ⇄
    A2A

    Convert to a real DataPart

    ADK's part_converter unwraps the tag into a genuine A2A DataPart — structured data with a mimeType, not text.

    DataPart(
  data     = { surfaceUpdate: {…} },
  metadata = { mimeType: "application/json+a2ui" }
)
  4. ↗
    A2A

    Travel over the A2A protocol

    The response is an A2A Message — the chat reply plus the A2UI DataParts — sent over the Agent-to-Agent protocol (JSON-RPC over HTTPS).

    Our agent on Vertex AI Agent Engine = A2A server Gemini Enterprise = A2A client
  5. ▣
    GE render

    Render natively in chat

    Gemini Enterprise identifies A2UI DataParts by their application/json+a2ui mimeType and renders them as live UI — no frontend code, no HTML, no iframe.

    Card · Table · Tabs · Slider · MultipleChoice · Modal · CheckBox · Icon …
  6. ⟲
    A2A

    Clicks come back the same way

    When the user taps a button, GE returns a userAction as an A2A DataPart on the next turn — the agent's callback dispatches it. No polling, no webhooks.

    userAction = { name:"select_restaurant", context:{ restaurant_id:"…" } }
One exchange, both directions: A2UI JSON as the content, A2A DataParts as the transport. Raw JSON printed into chat would just be text — it is the DataPart + mimeType that makes GE render it as UI.
